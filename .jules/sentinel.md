## 2025-02-14 - Prevent Information Leakage in Error Responses
**Vulnerability:** Information Exposure (CWE-209) through HTTP 500 error responses leaking raw database schema details, SQL syntax, or internal Redis connection details.
**Learning:** `sqlx::Error` and `redis::RedisError` can contain highly sensitive infrastructure details. If these errors are propagated to an HTTP response via the `Display` trait typically used for user-facing output (e.g. by using `thiserror`'s `#[error("Database error: {0}")]`), they can expose internals to an attacker.
**Prevention:** Do not format raw internal errors in `Display` implementations for enums representing errors that might be returned in HTTP responses. Omit placeholders like `{0}` in the `#[error(...)]` attribute (e.g., change `#[error("Database error: {0}")]` to `#[error("Database error")]`). The underlying error is still captured via `#[from]` and accessible via `Debug` (`{:?}`) for secure internal logging.
