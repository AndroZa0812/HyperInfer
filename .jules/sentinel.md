## 2025-02-24 - [Fix Reflected User Input in InvalidUuid Error]
**Vulnerability:** The application was reflecting untrusted, unsanitized user input (the invalid UUID string) directly in the `400 Bad Request` HTTP error response.
**Learning:** Returning unvalidated input directly in error messages can lead to Reflected XSS (if rendered by a client) or log forging. Rust's `thiserror` makes it easy to format strings, but we must be careful what strings we are formatting.
**Prevention:** Avoid allocating and reflecting raw user input in error enum variants like `InvalidUuid(String)`. Use static error messages like `InvalidUuid` for malformed input unless specific, sanitized context is required and safe to expose.

## 2024-05-24 - [SSRF Mitigation in HTTP Proxy]
**Vulnerability:** The proxy HTTP client (`reqwest::Client`) used `validate_base_url` which relied on synchronous IP checking, making it vulnerable to DNS Rebinding (TOCTOU). Additionally, the default HTTP client enabled redirects, potentially bypassing IP checks.
**Learning:** For defense-in-depth SSRF mitigation, checking the URL host pre-flight is insufficient. A custom DNS resolver (`reqwest::dns::Resolve`) must be employed to evaluate the actual IP addressed *after* DNS resolution but *before* TCP connection establishment. Furthermore, HTTP redirects must be explicitly disabled to prevent bypassing controls.
**Prevention:** Always implement a custom `reqwest::dns::Resolve` that filters resolved IP addresses against restricted ranges (RFC 1918, loopback, link-local, etc.) and explicitly set `.redirect(reqwest::redirect::Policy::none())` when creating the `reqwest::Client` used for proxying or fetching untrusted URLs. If standard library IP-checking functions are unavailable or flagged, use manual octet parsing to guarantee block enforcement.
