## 2025-02-24 - [Fix Reflected User Input in InvalidUuid Error]
**Vulnerability:** The application was reflecting untrusted, unsanitized user input (the invalid UUID string) directly in the `400 Bad Request` HTTP error response.
**Learning:** Returning unvalidated input directly in error messages can lead to Reflected XSS (if rendered by a client) or log forging. Rust's `thiserror` makes it easy to format strings, but we must be careful what strings we are formatting.
**Prevention:** Avoid allocating and reflecting raw user input in error enum variants like `InvalidUuid(String)`. Use static error messages like `InvalidUuid` for malformed input unless specific, sanitized context is required and safe to expose.

## 2025-02-26 - [Fix SSRF Vulnerability in Server Proxy via DNS Rebinding]
**Vulnerability:** The application used a default `reqwest::Client` in `hyperinfer-server/src/proxy.rs` to forward requests to external LLM providers using dynamically supplied base URLs. While synchronous URL parsing and IP checking was performed, it was susceptible to DNS Rebinding attacks. An attacker could provide a domain that initially resolves to a safe IP but subsequently resolves to an internal, non-routable IP (like `127.0.0.1` or `169.254.169.254`) when the client actually connects.
**Learning:** Synchronous, pre-flight host validation is insufficient to prevent SSRF due to Time-of-Check to Time-of-Use (TOCTOU) race conditions in DNS resolution.
**Prevention:** Always implement a custom `reqwest::dns::Resolve` trait (like `SafeResolver`) to asynchronously intercept and filter resolved IPs post-resolution, immediately before the connection is established. Ensure the HTTP client builder handles initialization failures securely (e.g., using `.expect()`) rather than silently falling back to a default, insecure client.
