## 2025-02-27 - [Fix SSRF vulnerability via DNS Rebinding]
**Vulnerability:** The application was vulnerable to SSRF bypasses via DNS Rebinding because it only checked literal IP address strings before resolution in `validate_base_url`. It also allowed HTTP redirects, which could be used to loopback to internal IPs.
**Learning:** In Rust using `reqwest`, synchronous pre-flight host validation is insufficient to prevent SSRF due to TOCTOU (DNS Rebinding) vulnerabilities. A custom `reqwest::dns::Resolve` trait is required to filter IPs asynchronously post-resolution, and HTTP redirects must be explicitly disabled.
**Prevention:** Always implement a custom `reqwest::dns::Resolve` trait to filter IPs asynchronously post-resolution and disable redirects using `.redirect(reqwest::redirect::Policy::none())` when creating the HTTP client.
